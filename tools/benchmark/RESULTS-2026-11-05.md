# CPU and allocation improvements, 5 November 2026

Three hot paths were changed without reducing graphics settings, animation frequency, simulation frequency,
network precision or packet contents. The measurements below cover those paths; they do not establish a
whole-game FPS gain or lower Internet latency.

| Path | Before | After | Measurement |
|---|---:|---:|---|
| Network serialization | 375.627 ms | 94.798 ms | 200,000 eight-actor batches, Release median of seven alternating samples |
| Network deserialization | 259.199 ms | 170.150 ms | Same workload and sampling |
| Bot reachability scratch allocation | 27,832 bytes/search | 0 bytes/search | Warmed 6,400-node graph, 128 searches against frozen baseline assemblies |
| Unchanged actor-light uploads | 106,496 native writes | 0 native writes | 8,192 applications after the first complete upload |

The codec uses the same UE2 variable-length integer encoding, deriving the bit count directly and moving
unconditional bits in byte-sized chunks. Both benchmark variants allocate zero bytes. Independent legacy
per-bit oracles check small exhaustive domains, full-width boundaries, random values, byte alignments,
truncation, overflow, reset and rewind. Packet length, quantization and the protocol contract are unchanged.

Each bot owns a reusable reachability cost array, and the graph retains a separate Dijkstra queue. Every query
still recomputes current costs and blocked routes. The existing allocating API returns independent arrays.
All costs matched the baseline for 64 origins; tests also cover changing blockers, cost limits, unreachable
nodes and a reachability query inside an active A* callback. These figures measure scratch allocation,
not all allocations in a bot decision. Each bot retains one float per graph node while it lives.

Actor-light uploads retain copied uniform values under weak node keys. Only identical native writes are
skipped; light selection and shaders are unchanged. Changed values, removed lights and Echelon changes are
still submitted immediately. The cache does not keep freed nodes alive.

In the Debug renderer fixture, 8,192 unchanged applications took 16.43 ms before and 1.25 ms after, with zero
managed allocation after warm-up. When all 13 uniforms changed, both paths submitted every value; the same
diagnostic run took 16.99 ms before and 18.18 ms after. Comparisons add overhead when nothing can be reused.
These single-run timings were collected during other correctness tests and should not be treated as an FPS
benchmark. The native-write counts and exact parity checks are deterministic.

## Validation

- Debug and ExportRelease client builds: no warnings or errors.
- Network library: 270 Release tests passed.
- AI tests: 171 passed, five optional long-match cases skipped; the normal SteeE match ran.
- Broad integration suite: 735 passed, 33 skipped, one pre-existing bandwidth-budget failure (details below).
- Animation parity: 4,880 exact cached/uncached poses.
- HUD replay: all 1,440 frames across both roles and three resolutions matched the pre-change fingerprints.
- HUD regional/full-copy images match at 640x480, 1920x1080 and 3440x1440, including changing scenery.
- Rendering: 1,024 exact light-selection comparisons and 126 exact image comparisons across normal,
  thermal and EMF views, changing/empty light sets, mutable inputs, material/mesh replacement, reparenting
  and node recreation. A normal-view control proves actor pixels respond to removal/restoration of lights.
- Rendered AquaE UDP lab: delayed loading, firing at a crouched target, damage/ammo agreement and reloading
  passed with 100 ms delay each way, 30 ms jitter, 3% loss and 0.5% duplication.
- Rendered dedicated-session smoke: three moving remote pawns, 775 coherent snapshots at 200 ms,
  maximum measured render-motion error 0.047 uu across 229 samples.

The strengthened actor fixture initially exposed an incorrect test-camera layer mask: it included the shadow
pass, producing black depth-only actor pixels. The fixture now uses the main-view mask and proves a visible
lighting response before accepting equal images. No production rendering change was required for that fix.

The integration failure is `BotMatchTests.StoryMatchOnSteeE(C, spies, 63)`: Spy1 receives a rounded 12,432 B/s,
above its 12,288 B/s limit. The unchanged test also fails at the same rounded rate with all nine pre-change
libraries copied from the frozen Debug build into an isolated test directory. Both matches complete after
11,728 frames with matching game results and no resynchronizations. Library hashes and loaded paths were
verified. This confirms the existing budget failure; differing Debug/Release configurations and slightly
different payload totals do not establish byte-identical whole-match replays. The threshold was not changed.
The broad suite's skipped cases require unavailable TestBox character data or opt-in long-match variants.

Run the focused checks from the repository root:

```powershell

dotnet test --project tests/OpenScct.Game.Tests -c Release -- --filter-class 'OpenScct.Game.Tests.AI.*'
dotnet test --project tests/OpenScct.Integration.Tests -c Release -- --filter-not-trait Category=Slow

./tools/ci/godot-smoke.ps1 -SkipBuild -Tests hud-output-replay,presentation-performance,hud-performance -ExpectedFailures @()

```
