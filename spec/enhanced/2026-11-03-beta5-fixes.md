# Enhanced Beta 5 audit implementation

Follow-up to [the audit](2026-11-03-beta5-parity-sweep.md), on `fix/enhanced-beta5-parity`, based on
`12666be6fbfeeb59c28358d3d9337965ca315fc1`. This work implements the requested gameplay/server fixes first,
then the remaining supported parity changes. The original audit remains a historical snapshot.

Further concrete bugs emerged while checking these changes:

- Spy bullets had inherited the wall-only sticky-camera trace filter and could not hit pawns. Their trace now
  includes pawns explicitly, with living/dead target regressions.
- The ledge-fall divergence came from collision ordering. Native BSP collision shortens the actor sweep before
  the mesh collision margin is calculated. Matching this order fixes the complete fall recording without
  changing tolerances or hiding frames. Authority contact queries deliberately request the nearest hit.
- The MSAA post-processing path requested the multisampled colour image, then rejected it as an unsupported
  storage/copy target. Explicit resolved colour/depth access restores the display-to-linear conversion and
  prevents incorrect brightness. The unchanged fog pixel checks now pass with 4x MSAA as well as without it.
- Rapid menu context changes could run a deferred focus request after its button left the scene tree.
  Deferred focus now revalidates the control before using it.
- Moving fog to individual surfaces exposed older gameplay effects still using standard Godot materials.
  Their unlit material subset now uses the same fog path, while preserving texture/UV animation, blending,
  billboards, weapon stencil masks and additional material passes. Paired GPU references check the migration.

## Data and compatibility

No source assets or decompiled code are tracked. Converted maps, screenshots, native evidence and local test
logs stay in ignored `.content/` or `local/`. The supplied Enhanced installations remain read-only.

Database schema 10 adds nullable loadout metadata; old rows keep null rather than inventing equipment history.
Numeric career counters retain their existing accumulation rules. Demo v2 changes the file container, not the
game network protocol hash. Older demo files remain readable; new v2 files need the updated reader.

The local moon updates use already published content packs. New MaterialSequence and fog metadata needs a
future conversion/content-pack release to reach other installations. All 83 maps supplied in the B5 install
were reconverted locally, including their map-audio followers. MoonD, the remaining animated-sequence corpus
map, was reconverted from the existing local source verified against its published original-content archive;
its gameplay, collision, traversal, UI and audio files remain byte-identical to that pack. Other maps outside
the supplied set were preserved. This task does not publish or deploy.

## Acceptance boundaries

- The retained movement recordings are B3 reference evidence; passing them is not a fresh B5 runtime matrix.
- Demo POV is sampled at 10 Hz and stamped at server receipt. It is closer to the actual player's rendered
  view, but is not frame-perfect capture or an Enhanced demo-format compatibility claim.
- Synthetic, installed-content and GPU checks establish their stated paths. They do not substitute for
  visual/audio comparison in the original or public multiplayer tests across latency, loss and frame rates.
- The animation pose matches the rewrite renderer; native bone-controller semantics still include the
  documented estimates. Original-game shot-by-shot hit-zone comparison remains an acceptance check.
- Complete-state MaterialSequence changes support every shipped sequence. Fading between incompatible
  complete render states is rejected explicitly; no supplied sequence requires that combination.
- No supplied map contains an authored SFogVolume. Volume construction and rendering use synthetic fixtures,
  including a synthetic fog actor around one brush from the owner's install.
- Native fog draw-role selection and the exact corona/light-beam fog-enable flags are not fully resolved.
  The native half-step (`+/-0.5/255`) fog dither is omitted pending that evidence; very subtle banding can differ.
  Unregistered diagnostic cameras retain the opaque-depth compositor fallback and its transparency limitation.
- The native binary comparison was focused, not whole-program semantic equivalence. Any unresolved fog,
  transparency or animation conditions must remain listed rather than folded into a blanket parity claim.
- B5 contains guarded shader source for fog-parting trails, but the inspected build does not enable it.
  All ten `FOG_TRAILS` byte occurrences are conditional guards; the shader builder defines only its visible
  portal and trail-word counts. Both buffer creation and upload reserve the header plus volume pieces only
  (`0x3280` maximum bytes), with no trail array. An active trail lifecycle was therefore not invented.
- The source-data guard currently reports seven unrelated concurrent website showcase images outside its
  permitted media paths. No audit-owned file was reported; those website edits have been preserved.
