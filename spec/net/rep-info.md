## Purpose

The always-relevant information actors: one `PlayerReplicationInfo` (PRI) per player, the single
`GameReplicationInfo` (GRI), the two team infos, and the level and zone infos. They carry the match
state every client shows (lives, score, time, objectives, teams, the traversal activation mask). The
plan's `SPlayerReplicationInfo` and `SGameReplicationInfo` do not exist in the game: `SGameInfo` and
`SPlayerController` use `Engine.PlayerReplicationInfo` and `Engine.GameReplicationInfo` directly
(`PlayerReplicationInfoClass`, `GameReplicationInfoClass` defaults), and those Engine classes already
hold the SCCT fields (`NumLives`, `GameMode`, `TeamLivesATT`, and so on).

## Rules

1. **PRI ownership.** A controller with `bIsPlayer` spawns its PRI on the server with itself as
   owner, so the owning client may call the PRI's client-to-server functions.
2. **PRI client functions.**
   - `setVisibleFromDedicatedServer(b)` (reliable, simulated, client to server):
     `bVisibleFromDedicatedServer = b`.
   - `UpdateMinimapParams()` (reliable, client to server): for every player controller with a pawn and
     a PRI, set that PRI's `MinimapX/Y/Z = int(Pawn.Location)` (truncated) and `MinimapYaw =
     Pawn.Rotation.Yaw`; if the yaw equals the previous value add 1 (forces a change so the value is
     re-sent); if it equals -1 set 0. A controller without pawn or PRI sets the calling PRI's own
     `MinimapYaw = -1` (not the other player's) and goes on.
   - `playerQuitMatch()` (reliable, simulated, client to server): `bQuittedMatch = true` (logged).
3. **PRI server timer.** `Timer` (server only): update the player location volume, re-arm for
   1.5 + FRand() s, then with probability 0.35 refresh `Ping` from the controller unless
   `bReceivedPing`. `Ping` replicates to everyone except the owner.
4. **PRI registration on clients.** `PostNetBeginPlay` (simulated) adds the PRI to the first GRI found
   (`AddPRI`); `Destroyed` removes it.
5. **GRI clock.** The server's GRI `Timer` (every 1.0 s, server only) advances `ElapsedTime` by 1 per
   `TimeDilation` seconds and counts `RemainingTime` down unless `bStopCountDown`; `RemainingMinute`
   seeds it once. Clients show the replicated integers. `PreciseElapsedTime()` = `ElapsedTime +
   (Level.TimeSeconds - SecondCount) / TimeDilation` is server-side (used for objective
   `TriggerTime`). On a client `PostBeginPlay` blanks `ServerName`, `AdminName` and `AdminEmail` until
   replicated.
6. **GRI members** (always, everyone): mode and rules (`GameMode`, `TimeLimit`, `NumObjectives`,
   `NumDisks`, `NumDisksToWin`, `TotalTeamLives[2]`, `TeamLivesATT`, `TeamLivesDEF`, `TimesRespawn`),
   timing (`ElapsedTime`, `RemainingTime`, `LastTimeObjectif`), match flow (`bMatchLaunching`,
   `bMatchLaunchingNow`, `bMatchHasBegun`, `bStopCountDown`, `WinningTeam`, `WinningReason`), teams,
   server identity, voice settings and gadget availability flags `bAvlb_*`. Admin and region strings
   go only in the first bunch.
7. **Traversal mask.** `LevelInfo.GEActivationMask` (byte) replicates whenever it changes (condition
   `Role == ROLE_Authority`). It is written only on the server by `SGETrigger` (class `RemoteRole`
   None): `Trigger` ORs `GEMask` in unless `bToggle` and all its bits are already set, in which case it
   clears them; `UnTrigger` clears them. Clients test GE records against the replicated mask. The
   `LevelInfo` is the one `bStatic` actor that is replicated (`model.md` rule 12).
8. **Other LevelInfo members** (dirty): `NbPointsDefense`, `NbPointsAttack`, `DefaultGravity`, `Pauser`,
   `TimeDilation`.
9. **ZoneInfo.SkyZone** is declared replicated, but `ZoneInfo` has `RemoteRole` None, so it never
   leaves the server; zones come from the map on both sides.

### Native PostNetReceive (decoded, editor 0x110b32b0, 0x110b37e0)

- PRI on a client: for the local player's own PRI, `Ping` is adjusted by the connection's measured time and
  floored at 0; a changed `PlayerName` raises `ClientNameChange`, a changed `CharacterName` raises
  `UpdateCharacter`.
- `LevelInfo`: only the Actor behaviour; nothing is done for `GEActivationMask` (the GE queries read the replicated
  mask directly each time, `movement/native-contracts.md` GE rule 2).

## Network

Server writes all variables; every client receives them (`bAlwaysRelevant`) except `Ping` (not to the
owner), first-bunch-only fields, and the never-sent `SkyZone`. The owning client of a PRI can call its
three functions.

## Edge cases

- `MinimapYaw` is nudged by +1 when unchanged so that it is always dirty; ports must keep the nudge or
  clients see stale minimap entries.
- The `UpdateMinimapParams` bug that writes -1 into the caller's own `MinimapYaw` when another player
  has no pawn makes the caller's minimap marker flicker to "no pawn" until the next update.
- PRIs update at most 5 times per second, so `NumLives` and score changes reach clients up to 0.2 s
  late; the GRI clock at most 10 times per second.
