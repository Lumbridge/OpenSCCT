## Purpose

What the server replicates for player pawns (`Engine.Pawn`, `SBasePawn`, the spy `SPawnAttaque` and
the merc `SPAWNDEFENSE`; the slice spawns their `_1Mesh` subclasses), who receives each member, and
what each group is for. Moving parts (position, actions, aim) are explained in `proxy-pawns.md`;
this file is the complete member list and the pawn-level RPCs.

## Data

Network defaults (`def:`):

| Class | RemoteRole | bAlwaysRelevant | NetUpdateFrequency | NetPriority | Other |
|---|---|---|---|---|---|
| `Pawn`, `SBasePawn`, `SPawnAttaque`, `SPAWNDEFENSE` | SimulatedProxy | false | 100 | 2.0 | `bUpdateSimulatedPosition`, `bNoRepMesh`, `bUseCompressedPosition`, `bStasis`, `DrawType` `DT_Mesh` |
| `SPawnAttaque_1Mesh`, `SPawnDefense_1Mesh` | SimulatedProxy | true | 100 | 2.0 | as above |

On possession `RemoteRole` becomes `ROLE_AutonomousProxy` (owner) and `NetPriority` 3.0
(`model.md` rule 4). `SGameInfo` spawns `SPawnAttaque_1Mesh` for spies and `SPawnDefense_1Mesh` for
mercs (`staticPawnClass`, `SGameInfo.uc`).

## Rules

1. **Tables.** Each member below is sent under its condition (`model.md` rules 5 to 9). "Blk" is the
   replication block index, "Dir" is server to client (S to C) or client to server (C to S), "Rel" is
   function reliability, "Sim" marks simulated functions. All four classes are nativereplication: the
   native lists (Evidence) evaluate the variable conditions.
2. **Pawn groups.**
   - Block 0 (dirty, everyone): typing, gravity, crouch and walk flags, last hit damage type,
     `AnimAction`, `PlayerReplicationInfo`, `TakeHitLocation`.
   - Block 1: `TearOffMomentum` once the pawn is torn off.
   - Block 2 (owner only): movement tuning (`AirControl`, `JumpZ`, `AccelRate`, `AirSpeed`,
     `GroundSpeed`) and `Controller`. Non-owning clients therefore always see `Controller == None`,
     which the script uses as "this is somebody else's pawn" (`PostNetBeginPlay`,
     `ClientPlayLandingSound`, `ChangeEnumAction`).
   - Block 3: `Health` to everyone when dirty.
   - Block 4: `PawnPosition` to non-owners (see `proxy-pawns.md` rule 10).
3. **SBasePawn groups.**
   - Blocks 0 and 1: landing sound RPCs (`proxy-pawns.md` rule 9).
   - Block 2 (client to server, reliable): spy bullet marking (`DetectedByMarqueurSpy`, native) and the
     camera-network vision switch request.
   - Block 3 (always, everyone): the two backpack slots shown to team mates (`aBackPackOwner_A/B`,
     gadget ids `aIDGad_Mate_A0..3`/`B0..3`, charges `aNbChargesGad_Mate_A0..3`/`B0..3`), `bPoisonned`,
     `bGasMask`.
   - Block 4 (everyone except the owner): packed aim `iDesiredYawPitch`, `iYawPitchFromView`.
   - Block 5 (always): own gadget charges `aNbChargesGad0..3`, `aGadgetType[4]`, `PoisonnedBy`,
     `CarriedFlag` (the disk), `HandItem`, `UsedObject`; server-to-client `UpdateInventory`
     (simulated) and `TellClientToTestAndSetEMFVisible` (not simulated, so only the owner runs it).
   - Block 6: glass (cloak) effects and the camera-network vision switch, simulated, meant for all
     clients (`model.md` rule 10).
   - Block 7 (client to server, reliable): grab counter mashing, gas mask, spy bullet hit, inventory
     spawning and deletion, EMF visibility on and off, glass effect requests.
   - Block 8 (always): `bSpyBulletOn`, `bCanBeGrabbed`, `iTeamSpying` (float), and the four partner
     references `m_PawnToTerminate`, `m_AttackedBy`, `m_AttackTarget`, `m_InteractionTarget`.
   - Block 9 (first bunch only): pose and action snapshot (`proxy-pawns.md` rule 5).
   - Block 10 (owner only): `MyGadget`, `MyWeapon` heads of the inventory lists and
     `AddDefaultGadgets` (simulated; its condition includes `bNetOwner`).
4. **SPawnAttaque**: `NbPointsRefillable`, `BloodDropStartTime` (health refill and blood trail) and
   the third-person weapon `WeaponDummy` (an `SWeaponAttaque`).
   **SPAWNDEFENSE**: `TorcheLaser`, `Torche` (the merc's light gadgets), `bLaserOn`, and
   `WeaponDummy` (an `SWeaponDefenseDummy` attached to bone `B R Hand`).
5. **Client-side helpers spawned locally, not replicated.** The goggle beam (class `RemoteRole`
   None) is spawned per machine and attached to `B Head`: `SPawnAttaque.PostBeginPlay` spawns
   `SGoggleBeam_ATT` (relative yaw 1500) wherever the pawn's `RemoteRole` is not
   `ROLE_AutonomousProxy` at that moment (before possession that is every machine);
   `SPAWNDEFENSE.PostBeginPlay` spawns `SGoggleBeam_DEF` (relative yaw 1250) on clients, in standalone
   and on a listen server, not on a dedicated server. `SBasePawn.PostBeginPlay` spawns
   `SFlicFlocEmitter` on every machine.
6. **Inventory requests.** `UpdateInventory` runs on the client that owns the pawn (called by
   `SGameInfo` with the match mode), reads the player profile and asks the server to spawn each item
   with `ServerSpawnInventory(class)` and `ServerSpawnWeapon(class)` (reliable). On a non-owning
   client the call has no effect (no profile controller, and calls on unowned actors are not sent).
   Default kit without a profile: spy smoke, chaff, sticky cam, heartbeat sensor, sticky shocker (plus
   the bomb in Sabotage and multi modes); merc frag grenade, multi mines launcher and more (see the
   inventory spec).

### Native lists (decoded, net-replists.md rule 12; editor 0x1120c9d0)

- Aim variables (`iDesiredYawPitch`, `iYawPitchFromView`) go only to non-owners, at most every 0.09 s; the
  `AllActions` group goes to non-owners in the first bunch only; the Actor list runs at most every 0.09 s.
- The Pawn list is bypassed: `PawnPosition`, `bIsWalking`, `bIsTyping`, `GroundSpeed`, `AccelRate`, `AirSpeed`,
  `JumpZ` and `AirControl` are never sent, and `bIsCrouched` only in the first bunch. The pawn list sets
  `bCompressedPosition`, so the position travels only through the RPCs of `proxy-pawns.md`.
- The pawn list resends `bEMFIsOn`, `EMFOpacity`, `EMFIntensity` and `HeatIntensity` on every change (the Actor
  list sends them only in the first bunch).

## Network

Server writes all variables; the owning client receives owner-only blocks (Pawn block 2, SBasePawn
block 10) and everything except block 4; other clients receive everything except the owner-only
blocks. Client-to-server functions are callable only from the owning client.

## Edge cases

- `iTeamSpying` is a float although its name suggests an int.
- Partner references (`m_AttackedBy` and the rest) are sent both as variables (block 8) and inside
  the action RPCs of `proxy-pawns.md`; the RPC values overwrite the variable values on receipt.
- Block 9 values are stale on clients after the first bunch until an action RPC refreshes them.
