# Editor windows and breakable glass

OpenSCCT's window enhancement uses ordinary `SBase.SVitre` actors with explicit generated meshes. Frame geometry is
separate and remains solid when glass breaks. The Editor packages shaped glass, collision, tinted and frosted
materials in the map; no new gameplay class or SVMap format is required.

Planar panes fracture into deterministic irregular cells clipped to their actual mesh triangles, retaining curved
outlines and holes. The authoritative damage hit position and direction travel with each pane's replicated break
state. Clients create impact-centred chips and larger fragments with gravity, level collision, settling and fade.
Late joiners see the broken pane without replaying debris. Nonplanar props keep the original emitter fallback.
Damage rules, sounds, events and blocking remain server-authoritative. This is an original procedural effect,
inspired by modern glass destruction; it is separate from original-game rendering parity.

New Editor builds can package optional `render/window-lighting.json.gz`, schema version 1. It contains sparse
unfiltered light contributions, pane transmission factors, atlas padding dependencies and cached bounce transport.
The runtime recombines these when replicated panes break or reset, updating existing lightmap textures and affected
static mesh vertex colours. Opaque occlusion and frame shadows remain baked. Overlapping panes multiply their
remaining transmission. Older maps without this file retain their existing lighting. Rebuild maps with the new
Editor to enable the response. Dynamic/switchable light transmission and optical refraction are outside this feature.

Validation: `GlassFractureTests`, `WindowLightTransferTests`, `GameplayObjectTests` and `GlassImpactNetworkTests`
cover clipped fragment area, UVs, deterministic impacts, lighting composition, damage metadata and connected/late
clients under latency/loss. The explicit renderer smoke `--svm-smoke=window-break` requires
`SVM_WINDOW_TEST_MAP=<compiled GlassLight folder>` generated by the Editor's `tools/window-light-checks` suite.
`SVM_PLAY_SHOTS` chooses its screenshots folder; `SVM_WINDOW_CLOSE_VIEW=1` chooses the close camera. It damages three
real compiled panes and checks fragment cleanup, replicated impact, cleared collision, GPU lightmaps and vertex
lighting. It is deliberately opt-in because the fixture comes from the Editor repository.
